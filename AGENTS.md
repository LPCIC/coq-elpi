# Ground rules for coding agents

## Build and test
- Build the plugin and the core theories with `make build-core`, the apps
  with `make build-apps`. `make build` builds the installable package.
- Run the core tests with `make test-core`, the apps' tests with
  `make test-apps`; `make all-tests` runs everything (also the tests needing
  the Rocq standard library). A single test file can be checked with
  `etc/with-rocq-wrap.sh dune build tests/NAME.vo`.
- New tests go in `tests/NAME.v` (every `.v` file there is part of the
  `elpi.tests` theory); API tests are named `test_API_*.v`.
- The dune files use the Coq rules (`(using coq 0.8)`), which dune 3.24
  dropped: build with an older dune.
- `builtin-doc/coq-builtin.elpi` (and the other files in `builtin-doc/`) are
  generated by the build from the declarations in `src/rocq_elpi_builtins.ml`
  and from `elpi/*.elpi`. Never edit them by hand; rebuild and check their
  diff.

## Elpi code (tests, examples, the manual)
- Give `pred` and `func` their signature with an arrow, inputs before it and
  outputs after it: `pred lookup string -> int.`, not
  `pred lookup i:string, o:int.`.
- Write a colon after the names of a `symb`: `symb red : color.`, also
  `symb red, green : color.`.

## OCaml code
- Do not use polymorphic equality (`=`, `<>`, `compare`, `List.mem`) when a
  dedicated function exists: `String.equal`, `Int.compare`, `Id.equal`,
  `Evar.equal`, `GlobRef.CanOrd.equal`, `Option.is_none` /
  `Option.is_some`, `List.exists (String.equal x)`. Plain `=` stays
  acceptable on ints, chars and variants without an `equal`.
- Keep the code compatible with OCaml 4.14: for example no `List.is_empty`.
- The plugin supports several Rocq versions (see `Changelog.md`); code
  depending on the version goes under `[%%if coq = "9.0" || ...]`
  (ppx_optcomp), following the existing examples.
- Builtins are declared in `src/rocq_elpi_builtins.ml` (`MLCode`, `MLData`,
  `LPCode`, with `In`/`Out`/`CIn`/`COut` and a context such as
  `Full(proof_context, ...)`); follow the existing entries and give each one
  a doc string, since it ends up in `builtin-doc/coq-builtin.elpi`. A builtin
  that fails (logically) raises `No_clause`; a misuse is reported with
  `err`.

## Reference manual (`docs/base`, Sphinx)
- Build with `make refman-build`; it runs Sphinx with `-W`, so it must stay
  free of warnings. The `.. rocqtop::` blocks run through a real `rocq top`
  with rocq-elpi installed.
- Verify every fact against the implementation (run it), not against other
  documentation.
- Terminology: a `pred` / `func` line is a *signature*; a `head :- body` unit
  is a *rule*, never a *clause*.
- A `:doc:` / `:ref:` link is never the subject or predicate noun of a
  sentence: write "is described in :doc:`x`", not ":doc:`x` describes".
- No `**bold**` in prose; `*italic*` for a term's first use, ``literal`` for
  code.
- Do not reintroduce text a maintainer deleted.

## Workflow
- User-visible changes get an entry in `Changelog.md` under `# Unreleased`
  (create the section at the top if missing).
- Never commit unless asked to. Commit messages have no `Co-Authored-By`
  trailer.
- A fix to work not yet merged is folded into the commit it belongs to
  (`git commit --fixup` then an autosquash rebase), not added as a new
  commit.
